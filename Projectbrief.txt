Creator Compass — Project Brief
1. Project Overview
Project name: Creator Compass
Project type: AI-assisted YouTube channel discovery and opportunity analysis dashboard.
Primary objective: Help aspiring YouTube content creators identify 2–3 promising channel ideas based on their strengths, interests, audience search interest, existing YouTube creators, and potential unmet audience needs.
Core problem: Many people want to become content creators but do not know what content to create, whether people are interested in those topics, who their competitors are, or how to differentiate themselves.
Creator Compass should help users move from:
"I want to start a YouTube channel, but I don't know what to create."
To:
"Here are 2–3 channel ideas suited to my strengths, with evidence of audience interest, relevant creators to learn from, and possible differentiation opportunities."
2. Project Philosophy
This is a personal portfolio project and an experiment with Codex, not a production-scale startup.
The project should demonstrate:
Consumer insights and understanding of audience needs
Market research and competitive analysis
Product thinking and user experience
Brand differentiation and strategic recommendations
Practical application of LLMs and analytics
Ability to build an end-to-end product using Codex
Priorities:
Working end-to-end functionality
Meaningful, evidence-backed recommendations
Simple and intuitive user experience
Transparent analytics
Clean and presentable dashboard
Reasonable implementation effort
Avoid overengineering, unnecessary infrastructure, custom model training, and advanced analytics unless essential.
3. Target Users
Aspiring YouTube creators who:
Have never created content before
Have several interests but don't know which to pursue
Have professional or personal expertise they might turn into content
Want to understand audience demand
Want to discover successful creators to learn from
Need help identifying a distinctive channel direction
4. Core User Journey
Step 1 — Understand the creator
Provide two input methods:
Method A: Guided questionnaire
Select interests from predefined categories
Select relevant skills and strengths
Add custom interests
Describe professional or personal expertise
Indicate preferred content style
Indicate available time and production constraints
Method B: Profile-based input
Paste LinkedIn profile text or upload a resume
Use an LLM to extract possible strengths, skills, expertise, and content interests
Allow the user to review and edit the extracted information
A LinkedIn URL can be accepted as a reference, but do not automatically scrape LinkedIn profiles. If the content cannot be accessed through a permitted method, ask for pasted text or a resume.
The creator must be able to edit their profile before proceeding.
Step 2 — Generate potential content topics
Use the creator's interests, strengths, and experience to generate a range of potential YouTube topics or niches.
Where available, incorporate Google Trends information to evaluate search interest.
Distinguish between:
Creator fit
Search interest
Topic coverage in the downloaded YouTube dataset
Do not confuse search interest with predicted YouTube success.
Generate understandable topic suggestions with short explanations.
Step 3 — User selects topics
This is a required step.
After the app suggests topics:
Display the suggestions as selectable cards
Let the user choose which topics to research
Allow editing or adding custom topics
Do not automatically assume that every generated topic interests the creator
Only selected topics should proceed to competitor and audience analysis.
If a selected topic has insufficient coverage in the dataset, display that limitation clearly.
Step 4 — Creator discovery and audience-gap analysis
For each selected topic:
A. Identify relevant creators
Search the local YouTube dataset for relevant videos
Identify the channels associated with those videos
Display relevant creator names or handles, when available
Show representative videos
Show available engagement metrics and content themes
Only use information actually present in the dataset. Do not invent missing creator statistics.
B. Identify potential audience needs
Retrieve a manageable sample of comments from relevant videos
Use an LLM to classify comments into categories such as:
Tutorial requests
Requests for practical examples
Unanswered questions or confusion
Requests for comparisons
Requests for greater depth
Requests for a particular audience or use case
General feedback / other
Aggregate recurring themes
Show representative comments and their associated videos
C. Identify possible content gaps
Compare recurring audience requests with the topics covered by sampled videos
Identify potentially underserved questions, audiences, formats, or use cases
Suggest differentiation opportunities
Treat these as hypotheses rather than proven market gaps.
Do not claim that a topic is missing across YouTube simply because it is absent from the downloaded dataset.
Important: Keep this analysis lightweight. Use straightforward filtering, sampling, and LLM classification. Avoid advanced NLP pipelines unless simpler approaches prove insufficient.
Step 5 — Channel recommendations and opportunity scorecard
Generate 2–3 channel concepts using the selected topics and available evidence.
For each recommendation, display:
Channel concept: What the channel would focus on
Target audience: Who it would serve
Creator fit: Why the idea matches the user's strengths and interests
Audience interest: Relevant Google Trends signals, if available
Existing creators: Relevant channels and videos to learn from
Potential differentiation: Specific audience needs or content approaches worth exploring
Opportunity score: A transparent comparison across candidate ideas
The scorecard should evaluate:
Creator fit
Search-interest signal
Competitive intensity
Strength of audience-gap evidence
Production feasibility
Allow users to adjust the relative weights.
Do not treat missing data as a zero score. Show missing or insufficient evidence explicitly and adjust the comparison accordingly.
The score is a decision-support tool, not a prediction of channel success.
5. Data Sources
Primary dataset
YouTube Comment Exposure Dataset
https://huggingface.co/datasets/brianhliou/youtube-comment-exposure
This is the first dataset to investigate.
It has been described as containing approximately 1.35 million comments across hundreds of videos and dozens of channels.
However, Codex must independently verify:
Actual dataset schema and row count
Video and channel metadata
Topic/category coverage
Comment text availability
Languages
Missing values
License and reuse restrictions
Whether it can support creator comparisons and audience-gap analysis
Do not assume the dataset is suitable until the audit is complete.
Backup dataset
https://huggingface.co/datasets/Arshia82sbn/youtube-sentiment-dataset
This is an alternative with more than one million comments, primarily designed for sentiment analysis.
Use it only if the primary dataset is unsuitable or insufficient, and audit it before use.
Google Trends
Use Google Trends for relative search-interest information and related queries.
For the MVP:
Prefer a small, documented dataset collected from Google Trends
Do not require access to a restricted API
Do not fabricate trend scores
Clearly distinguish unavailable trend data from observed values
YouTube Data API
Explicitly out of scope.
Do not build live YouTube video discovery or comment retrieval.
The app will operate on a static downloaded dataset.
Document the resulting limitations.
6. Data Processing Strategy
Do not send the entire dataset to an LLM.
Recommended workflow:
Download and inspect the dataset.
Convert it into an efficient local format if appropriate.
Index or query available video titles, channel metadata, and comments.
Match user-selected topics to relevant videos.
Select a manageable sample of videos.
Sample approximately 20–50 comments per video as an initial default.
Use structured LLM output to classify comments.
Aggregate themes and preserve supporting examples.
Compare recurring audience requests with available video coverage.
Generate evidence-backed channel recommendations.
Start with approximately 10–30 relevant videos per topic when the dataset supports it. These are engineering defaults, not statistically representative sample sizes.
Use caching where permitted and avoid repeating expensive processing.
7. Suggested Technology Stack
Prefer a simple Python-based implementation:
Streamlit for the dashboard
Python for application logic
Pandas or Polars for data processing
Parquet for efficient local data storage
DuckDB if fast analytical queries become necessary
An LLM API for topic generation, comment categorization, and recommendation explanations
Environment variables for API keys
Codex may recommend alternatives if the dataset audit reveals a clear reason.
Avoid unnecessary cloud infrastructure, vector databases, custom ML models, and complex backend services.
8. Dashboard Design
The app should feel like a polished, modern product rather than a technical notebook.
Design principles:
Guided step-by-step flow
Clean typography and generous spacing
Clear cards for topic selection
Simple competitor comparisons
Interactive scorecard with adjustable weights
Evidence attached to recommendations
Clear loading, empty, and error states
Easy navigation back to earlier steps
Prioritize clarity over the number of charts.
9. Important Limitations
Document the following:
Static dataset coverage The app cannot analyze topics, creators, or videos absent from the downloaded dataset.
Dataset age The dataset may not reflect current YouTube content or trends.
Sampling bias Commenters are not representative of all viewers.
Incomplete competitor analysis A dataset containing only a subset of videos cannot establish everything a creator has covered.
Uncertain differentiation Content gaps are hypotheses based on limited evidence.
Search-interest limitations Google Trends does not directly measure YouTube viewership or guarantee future demand.
Scoring limitations The opportunity score is a transparent heuristic, not a predictive model.
10. Success Criteria
The MVP is successful if:
A user can create or edit a creator profile.
The app generates relevant topic suggestions.
The user can select topics before research begins.
The app identifies relevant videos and creators from the dataset.
The app categorizes comments and identifies possible audience needs.
The app generates 2–3 channel recommendations where sufficient evidence exists.
The scorecard responds to changes in user weights.
Recommendations show their supporting evidence and limitations.
The complete workflow runs locally.
The repository contains clear documentation and setup instructions.
If the dataset cannot support a niche, the app should explain that rather than inventing recommendations.
11. Explicitly Out of Scope
Do not build:
Live YouTube API integrations
LinkedIn scraping
Automated thumbnail generation
Video script generation
Content calendars
Creator performance tracking
Channel growth forecasting
Advanced recommendation model training
Custom embeddings infrastructure
User accounts or authentication
Paid subscriptions
Production-scale cloud deployment
12. Development Approach
Build iteratively.
First audit the dataset, then build the basic interface, then implement topic matching and comment analysis, then add recommendations and scoring.
Use Codex to generate code, run tests, identify errors, and improve the product.
Keep modules separate, code readable, and the project easy to maintain.
At every phase, explain what was built, what was tested, what remains incomplete, and any important limitations.
Do not invent data, results, metrics, or implemented functionality.
